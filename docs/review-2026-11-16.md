# Post-release review — 16 November 2026

An Astra advisor reviewed source `0f3742614da98ef3c6ed574a6cdd30045e0392da` read-only. Targeted regression probes reproduced the findings below before implementation. All examples remain synthetic.

| Finding | Correction and regression coverage |
| --- | --- |
| A stale Run cache could forget an already-recorded execution and recreate a deleted Job. A stale Job cache could falsely report `JobMissing`. | Read both resources directly from the API server. Lock status patches to the original resource version. Tests cover both cache delays, a conflicting status write, status failure after creation, and replacement Job UIDs. |
| OPA could turn a builtin error into an undefined value, authorizing a rule through negation. | Enable strict builtin errors. Invalid timestamp strings and invalid input types now return an evaluation error and deny. |
| The scaffolded leader-election Role allowed writes to trusted ConfigMaps. | Remove its ConfigMap rule; leader election uses Leases. Kind checks effective read/write rights and Secret-read refusal as the runtime service account. |
| JSON accepted trailing content, and evidence integers could lose precision through floating-point decoding. | Require end of input after one JSON value and preserve numbers with `json.Number`. Tests include adjacent objects, garbage, and values above the exact float64 integer range. |
| Suspended Jobs or custom Job controllers could bypass the intended native execution lifecycle. | Reject `suspend: true` and custom `managedBy`. Existing deadline, retry, resource, ownership, and TTL checks remain. |
| Release lookup errors were treated as absence, allowing an image push before release creation failed. | Require a successful paginated lookup before Docker. Mocked 403/503, existing-release, and mismatched-metadata tests verify refusal before any Docker command. |
| Docker engines expose different meanings for `inspect .Id`. | Derive `image_id` from saved configuration bytes and check the loaded image through a second save. Test both classic and containerd archive layouts and changed configuration bytes. |

The Kind failure scenario also verifies the actual Job `Failed` condition and the Run's `JobFailed` reason, so an unrelated controller failure cannot satisfy it.

Validation uses race-enabled Go tests, Rego tests, release-script tests, a real envtest API server, vulnerability analysis, and separate Kind runs for the source controller and the packaged image/manifest. These scopes do not establish production adoption, trusted backup integration, or exactly-once worker effects. Runtime API reads add two direct reads per reconciliation; configuration watches retain their existing behavior.

This change updates source only. The published `v0.1.0` tag, image, and five assets remain unchanged and do not contain these fixes. Publishing a later version requires its own version update and release qualification.
